# План тестирования `threexui_inbound_client`

Дата: 2026-02-06

## 1. Подготовка

- [ ] Панель 3x-ui запущена, API доступен
- [ ] Существует хотя бы один inbound (vless)
- [ ] Очистить состояние TF/OpenTofu в `examples/`

## 2. Базовое создание клиента

- [ ] Создать клиента с минимальными полями (`inbound_id`)
- [ ] Проверить автогенерацию `client_id` (UUID)
- [ ] Проверить автогенерацию `email`
- [ ] Проверить, что клиент появляется в API (`settings.clients`)
- [ ] Проверить ID ресурса в формате `{inbound_id}:{client_id}`

## 3. Все поля клиента

- [ ] `email` — задать явно
- [ ] `security` — задать (например `auto`)
- [ ] `password` — для trojan-протокола
- [ ] `flow` — для vless (например `xtls-rprx-vision`)
- [ ] `limit_ip` — лимит IP
- [ ] `total_gb` — лимит трафика
- [ ] `expiry_time` — время истечения (unix ms)
- [ ] `enable` — true/false
- [ ] `tg_id` — Telegram ID
- [ ] `sub_id` — Subscription ID
- [ ] `comment` — комментарий
- [ ] `reset` — период сброса (дни)

## 4. Обновление клиента

- [ ] Изменить `email`
- [ ] Изменить `enable` true → false
- [ ] Изменить `limit_ip`
- [ ] Изменить `total_gb`
- [ ] Изменить `comment`
- [ ] Проверить, что `client_id` не меняется при обновлении
- [ ] Проверить, что другие клиенты в inbound не затрагиваются

## 5. Идемпотентность

- [ ] `apply` без изменений → `No changes`
- [ ] `apply` после ручного изменения клиента через UI → корректный drift
- [ ] Повторный `apply` после перезапуска панели

## 6. Несколько клиентов

- [ ] Создать 3 клиента в одном inbound
- [ ] Удалить одного — остальные на месте
- [ ] Обновить одного — остальные не затрагиваются
- [ ] Проверить порядок клиентов (не влияет на state)

## 7. Удаление клиента

- [ ] `destroy` одного клиента → удаляется из API
- [ ] `destroy` последнего клиента → обработка ошибки "no client remained in Inbound"
- [ ] После удаления клиента inbound остаётся

## 8. Протоколы

- [ ] Клиент для `vless` — `client_id` = UUID, `flow`
- [ ] Клиент для `vmess` — `client_id` = UUID, `security`
- [ ] Клиент для `trojan` — `client_id` = password
- [ ] Клиент для `shadowsocks` — `client_id` = email

## 9. Import

- [ ] Import клиента по `{inbound_id}:{client_id}`
- [ ] Проверить корректность state после import
- [ ] Import несуществующего клиента → ресурс удаляется из state

## 10. Мьютекс (конкурентный доступ)

- [ ] Одновременное создание нескольких клиентов (parallelism > 1)
- [ ] Проверить отсутствие race condition

## 11. Негативные сценарии

- [ ] Несуществующий `inbound_id` → ошибка
- [ ] Дублирующийся `email` → ошибка API
- [ ] Пустой `client_id` при trojan (пустой password) → ошибка
- [ ] `inbound_id` = 0 → ошибка

## 12. Взаимодействие с inbound

- [ ] Обновление inbound не удаляет клиентов
- [ ] Удаление inbound при наличии клиентов → каскадное удаление
- [ ] `ensureInboundClientsKey` — inbound без `clients` в settings → корректно добавляется

## 13. Результаты

- [ ] Все пункты выполнены
- [ ] Зафиксированы отклонения/баги
